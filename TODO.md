# Known gaps and ideas

Roughly in order of how much they matter for users. See also the open items in
[docs/propagation-support-counting-spec.md](docs/propagation-support-counting-spec.md).

## Missing features

- **Rotation and reflection helpers.** Tiles are plain data, so variants have to be generated by the caller (see `examples/node/variants.mjs`). `TileDef.rotation` and `TileDef.reflection` are metadata only: `TilesetImporter` passes them through but nothing generates variants from them.
- **Boundary conditions.** Grids have hard edges; there is no wrapping (torus) or mirrored boundary.
- **Fix or remove `TriangularGrid`.** Its neighbour relation is not reciprocal (most neighbour pairs don't face back), so it is not exported. `docs/custom-grids.md` has a check that finds this.
- **Smarter backtracking for very large grids.** Restarts (spec, section 14) fixed mid-size grids, but 80×80 with the isometric tileset still needs ~19 restarts and ~2 s per run (9 of 10 seeds finish). Backjumping (jump back to the decision that actually removed the tile a cell needs, instead of the most recent one) would waste less work per failure; it needs "why was this tile removed" bookkeeping in `SupportPropagator`. Per-level retry limits are the other option.
- **Faster proofs with restarts on.** Restarts make proving "no solution" on hard instances up to ~15× slower (`restartAfter: 0` avoids it). Options: remember what earlier attempts refuted, or restart less while the search is clearly exhausting a small tree.
- **Faster cell selection on very large grids.** Choosing the lowest-entropy cell scans every cell each step; an entropy bucket or heap would remove that.

## API cleanup (before calling it 1.0)

- The adjacency grammar's quirks (two negations never match; values are alphanumeric only) are documented in `docs/adjacency-grammar.md` but could be revisited.
- Failures are still logged at `ERROR` level (now as one line, without a stack trace) as well as emitted and thrown; `LogLevel.NONE` silences it.
- `DefaultRandom` is `Math.random` until seeded. Whether an unseeded run should be reproducible by default is a design question.

## Project

- **Publish:** create the npm package (`npm publish`), then confirm the README's install command and CDN URL work. The package is configured (name, `exports`, `files`, `prepare`, CI, `npm run check:package`); publishing itself needs your npm account.
- **Code of conduct and security policy:** not included. GitHub offers the Contributor Covenant and a `SECURITY.md` template under the repository's Community Standards.
- `benchmark/` still uses a synthetic tileset where every tile matches every other; `stress-test/` is the more meaningful measurement.
- More tileset examples (a Wang-tile set, a Tiled-format importer, rules using the full grammar).
